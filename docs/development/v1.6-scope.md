# Repository Collaboration Workflow v1.6 Scope

## Purpose

Repository Collaboration Workflow v1.6 turns BrandOS GitHub, branch, review, and merge work into a
deterministic repository-first collaboration layer.

## Context

Operator Workflow Design v1.5 closed with deterministic Studio surfaces for choosing, sequencing,
inspecting, handing off, aggregating, and closing operator work. The repository now needs clearer
collaboration workflows so local Codex work, GitHub Desktop visibility, pull requests, review evidence,
and merge readiness can stay aligned without relying on chat history.

## Goals

- Add repository branch status surfaces that explain local branch, remote branch, and main branch state.
- Add pull request readiness summaries that explain whether work is ready to open, review, or merge.
- Add review evidence surfaces that track required checks, release notes, closure evidence, and unresolved blockers.
- Add merge readiness surfaces that keep main branch changes deliberate and auditable.
- Keep every repository collaboration behavior covered by fixtures, tests, checks, release notes, and closure checklists.

## Non-Goals

- Direct production deployment.
- External GitHub API automation beyond local repository evidence.
- Database integration.
- Authentication runtime.
- Live AI model execution.
- Multi-user permission management.

## Planned Packages

1. Repository Branch Status
2. Pull Request Readiness
3. Review Evidence Summary
4. Merge Readiness
5. Repository Collaboration Aggregate Summary
6. Repository Collaboration Final Closure

## Acceptance Criteria

- v1.6 scope and start decision are indexed.
- Studio can show deterministic repository collaboration state without external services.
- Repository collaboration behavior maps back to completed v1.1 through v1.5 runtime and workflow contracts.
- New fixtures and checks validate each package.
- Release notes and closure checklists exist for every package.
- Full repository validation passes before v1.6 closure.
